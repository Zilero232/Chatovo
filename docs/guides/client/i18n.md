# i18n

Every user-visible string goes through **`next-intl`**, in both locales. No string maps, no hard-coded text in components.

## Where the messages live

`shared/i18n/locales/{en,ru}/<namespace>.json` — one file per namespace (`admin`, `app`, `auth`, `common`, `marketing`, `room`, `social`), the same set of files and the same keys in both languages. `LOCALES` and `DEFAULT_LOCALE` are in `shared/i18n/config.ts`.

`apps/client/messages.d.ts` is generated: don't edit it by hand. It is also why ESLint ignores that file — next-intl augments its own module there, which only an `interface` can do.

## Reading them

- Client components: `useTranslations('<namespace>')`, plus `useFormatter` and `useLocale` when you need them.
- Server components: `getTranslations` from `next-intl/server` (see `views/home`).

## Locales and the URL

The marketing site carries its locale in the path: `/en/...` is English, everything else is Russian (`resolveLocaleFromPath` in `shared/i18n/config.ts`).

## The tests keep the locales honest

`shared/i18n/_tests/` holds three guards, and they run in `bun run test`:

- `locale-parity.test.ts` — `en` and `ru` have the same namespaces and the same keys.
- `error-locales.test.ts` — every server error code from `@chatovo/schemas` has a message in both locales; a missing one would ship as a blank error toast.
- `unused-messages.test.ts` — a key nothing reads any more fails the suite, so delete the key with the code that used it.
